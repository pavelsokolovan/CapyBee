# Spec 29.1 — Polish Authored Pack

**Type:** Implementation instruction
**Parent:** [Spec 29](29-capybee-polish-game-and-product-integration-instruction.md)
**Depends on:** 28.4
**Baseline:** `967e1d9`, inspected 2026-11-14
**Status:** Draft

## Scope and deliverable

Create `app/engine/reference-game-packs/capybee-new-hive/` as a new versioned
Pack (`capybee-new-hive`, initial `1.0.0`, locale/default `pl`). Do not rename,
overwrite or translate `lanterns-of-willow-marsh` in place. Preserve its saves
and certification fixtures. The new Pack must load, play and resume in the
unchanged universal runtime and console with no Spring, network or provider.

First implement an authored game with optional generation disabled. Use the
existing Pack schemas/validators and DSL, not new CapyBee-specific engine rules.
Register/copy its exact resources into the server's existing classpath Pack
catalog through the established packaging mechanism. Keep production rollout
flags unchanged. Development/operator allowlisting is explicit.

## Content contract

Write a reviewed content inventory alongside the Pack: scene/place/actor IDs,
choices, state effects, objective conditions, endings, and safe real-life-step
catalog bindings proposed for 29.4. Require at least six named places, three
fictional animal/abstract companions with a trait and a need, two optional
encounters, and three reachable resolutions. A route should fit a calm short
session, with no timed choices, grinding, mandatory combat or punishment.

Use Honeycomb Board geography, Befriend & Recruit encounters and Hive
Expedition scenes. Arrival, obstacles, helpers and resolution may branch/repeat;
this is not a mandatory linear emotional recovery arc. Joining a companion
records fictional cooperation, never a replacement for a real friend. Include
remembering the old home and discovering the new home without making either
world a wrong choice. The Old World motif stays a lantern; no padlocks, hearts
or human figures. Homesickness is normal, never something the child must fix.

All story/setup text in this Pack is reviewed Polish. Existing application
controls remain EN/PL; explicitly label the story language in either shell.
Resolve all labels through Pack resources and use public character/place IDs.
No external images, links, arbitrary HTML or newly generated asset URLs.

## Mechanics and endings

Use public `availableMoves`, visited/current place data, choices and explicit
advance. At least one route exercises movement and one explicit Continue.
Ensure optional branches can rejoin or end and no reachable state is stuck.
Any companion counter/flag has an explicit rule and readable supplied label;
do not introduce health, affection scores or a diagnosis merely for decoration.

Every authored ending offers one reviewed, optional real-world step in content,
including a gentle pause/rest choice. Suggestions are not automatically saved
or completed Missions. Abandon has no completion reward or pressure. There are
no web reward calls in this part; 29.4 owns product effects.

## Acceptance and gates

Use engine schema/boundary/playability checks plus deterministic console routes
covering all endings, optional companions, repeated visits, unavailable moves,
Polish characters and snapshot resume at each accepted revision. Store sanitized
route assertions; no real-child input is needed. Prove provider-disabled play
and that the old English Pack's save/certification fixtures still pass.

Run standalone engine `clean verify`, backend gate when registration/resources
change, and integrated Spring/browser smoke for selecting and resuming this
Pack. Record exact Pack version/fingerprint and reviewed content inventory.
Commit only this part after checks pass; it does not enable production starts.
