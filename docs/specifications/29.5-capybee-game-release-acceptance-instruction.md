# Spec 29.5 — Polish Game Release Acceptance

**Type:** Implementation instruction
**Parent:** [Spec 29](29-capybee-polish-game-and-product-integration-instruction.md)
**Depends on:** 29.1–29.4
**Baseline:** `967e1d9`, inspected 2026-11-14
**Status:** Draft

## Acceptance scope

Certify the exact Polish Pack/version, UI/server candidate and any generation
resources produced by 29.1–29.4. This is product acceptance beyond the generic
web client proof in 28.4. Keep generic/dynamic games, existing Pack saves and
mini-games compatible. Do not treat completion of this part as an instruction
to enable production flags or incur provider costs.

## Required matrix

- Authored Polish play reaches every resolution without a provider; optional
  companions, legal movement/Continue, repeated visits and gentle pause work.
- Generated runs use theme-first declared slots, reviewed Polish fallback,
  bounded cost and zero-provider distress/PII routing. Wishes/mood preferences
  pass privacy sentinels; no personal content reaches logs/history/metrics.
- EN and PL shell users see an explicitly Polish story with readable wrapping;
  map/list, keyboard, focus, 360px, zoom and reduced motion remain usable.
- Wait/202, lost start/command response, reload/PWA restart, offline safe intents,
  account changes, two tabs and provider/profile disablement preserve accepted
  state and never reconstruct private bodies or duplicate a paid start.
- A fresh server/process restores the same saved definition/content/fingerprint.
  Failure/cancellation before replacement preserves the previous run.
- Every eligible ending produces at most one trusted completion projection;
  forged results, abandoned runs and non-eligible sources produce none.
- Mission accept/dismiss/offline retry is optional and idempotent; no suggestion
  automatically completes a real-world step or exposes a transcript.
- All mini-games/RPG share one daily game-cell offer; midnight/DST, duplicate
  rows, replay, offline sync and multiple devices do not show duplicate cells.
- Existing English reference Pack and older authored/dynamic snapshots remain
  readable. Disabling new paid starts preserves saved-run reading/commands.

Use explicitly test-only generator/reviewer/guard/auth doubles and PostgreSQL
16; production profiles must not expose them. Automate state/network/storage
assertions, not screenshots alone. Manually inspect Polish copy and emotional
framing, keyboard/map/list navigation, assistive-technology output and actual
mobile PWA behavior. Record limits honestly if a device/provider was not tested.

## Gates and operator evidence

Run frontend coverage plus the documented build/static sync, standalone engine
`clean verify`, exact backend reactor `verify`, and Spring-served browser suite.
Build a candidate once; run package/verifier/failure-injection, authored/dynamic
offline certification and PostgreSQL migration/restart compatibility against
its exact bytes. Check GitHub workflow definitions and passing push/deploy
results. Do not lower thresholds, skip migration tests or rewrite saved formats
to make this Pack pass.

Write content-free evidence with source revision, Pack version/fingerprint,
artifact digests, locale/routes, browser/device versions, test commands/outcomes,
privacy cases and unresolved operator checks. Include no child data, prompts,
story dumps or credentials. Paid live certification needs separate explicit
operator authorization, reviewed provider terms, exact model/pricing and caps;
a deterministic PASS is not live Polish story-quality/cost certification.

Update `docs/game-web-client.md`, the specification index and rollout/rollback
instructions. Describe how to stop new generation without disabling saved
runs, protect forward migrations and retain previous Pack versions for saves.
Mark the parent implemented only when all parts and required acceptance pass.
Production activation remains an explicit operator action after review.
