# 10 — Memories Card Interactions: Icon Sizing, Favorite Pinning, Delete Undo

## Purpose

Follow-up implementation instructions for GitHub Copilot, building directly on
`09-memories-screen-redesign-instruction.md`. Covers three fixes reported after that
pass shipped: the favorite star and delete icons render too small to see/tap
comfortably, favorited memories should pin to the top of the list, and deleting a
memory needs an undo window matching the existing mission "Not today" pattern.

Applies to: `SCR-09 - Memory Space (Old World / New World)` (`/memories`).
Related docs: `09-memories-screen-redesign-instruction.md`,
`08-missions-redesign-instruction.md` (source of the undo-toast pattern being reused).
Related files: `app/ui/src/AuthenticatedHome.tsx` (memories tab), `app/ui/src/styles.css`.

---

## 1. Problem Being Fixed

- `.favorite-star` and `.icon-delete-button` (added in spec 09) rely on emoji glyphs
  (`★`/`☆`/`🗑`) sized by `font-size`. Emoji rendering size is inconsistent across
  fonts/platforms and reads as noticeably smaller than the rest of the card's text —
  confirmed in the latest screenshot, both icons are hard to see and were manually
  circled to be found.
- Favorited memories don't visually group together — a child has to scroll the whole
  list to find their favorites.
- Deleting a memory is immediate and permanent. Every other destructive/skip-style
  action in the app (mission "Not today") has a brief undo window; memories currently
  don't.

---

## 2. Icon Sizing — Replace Emoji Glyphs With Inline SVG

Emoji-as-icon is the root cause of the sizing problem — replace both icons with
inline SVG so size is explicit and consistent everywhere, matching the flat 2px-stroke
style already established for the honeycomb/banner illustrations.

Add two small local components near the top of `AuthenticatedHome.tsx` (or extract to
`app/ui/src/components/icons.tsx` if preferred — either is fine, keep it simple):

## 3. Favorite-Pinned Sorting

**Rule:** Favorited memories always sort above non-favorited ones. Within each group
(favorites, then non-favorites), sort stays descending by `createdAt` (newest first),
same as today. Unfavoriting an item drops it back out of the pinned group into its
normal date-ordered position — it does not jump to the top or bottom, just back to
wherever its date puts it among non-favorites.

Add a derived, sorted list instead of rendering `memories` directly:

```tsx
const sortedMemories = useMemo(() => {
  return [...memories].sort((a, b) => {
    if (a.isFavorite !== b.isFavorite) {
      return a.isFavorite ? -1 : 1;
    }
    return new Date(b.createdAt).getTime() - new Date(a.createdAt).getTime();
  });
}, [memories]);
```

Render `sortedMemories.map(...)` in place of `memories.map(...)` in the memories list
section. `memories` itself (from `fetchMemories(worldType)`) is unchanged — this is a
pure client-side re-sort, so no backend/API changes are needed.

## 4. Delete Undo (matches mission "Not today" pattern)

**Behavior:** Tapping the trash icon removes the card from view immediately, but the
actual `DELETE /api/memories/{id}` call is deferred for 4 seconds behind an undo toast
— identical timing/UX to `skipUndoMissionId` / `undoMissionSkip` in the missions flow.
If the child taps `Undo`, nothing is sent to the server and the card reappears
untouched. If the window elapses, the delete is committed as normal.

Unlike mission skip (which is backed by a lightweight interaction log on the server),
memory delete has no "undo" API — so the undo window is handled entirely client-side:
the DELETE request is simply delayed, not sent, until the window expires.

### 4.1 State (add alongside existing memory state)

```tsx
const [pendingDeleteMemoryId, setPendingDeleteMemoryId] = useState<string | null>(null);
const memoryDeleteTimerRef = useRef<number | null>(null);
```

### 4.2 Replace `deleteMemory` usage with a request/commit/undo trio

```tsx
const commitMemoryDelete = async (id: string) => {
  setPendingDeleteMemoryId((current) => (current === id ? null : current));
  try {
    await request<void>(`/api/memories/${id}`, { method: 'DELETE' });
    await fetchMemories(worldType);
    await fetchAllMemories();
  } catch (error) {
    console.error(error);
  }
};

const requestDeleteMemory = (id: string) => {
  // Only one pending delete at a time — if another is already waiting, commit it now.
  if (pendingDeleteMemoryId && pendingDeleteMemoryId !== id) {
    if (memoryDeleteTimerRef.current) {
      window.clearTimeout(memoryDeleteTimerRef.current);
    }
    commitMemoryDelete(pendingDeleteMemoryId);
  }

  setPendingDeleteMemoryId(id);
  if (memoryDeleteTimerRef.current) {
    window.clearTimeout(memoryDeleteTimerRef.current);
  }
  memoryDeleteTimerRef.current = window.setTimeout(() => {
    commitMemoryDelete(id);
  }, 4000);
};

const undoMemoryDelete = () => {
  if (memoryDeleteTimerRef.current) {
    window.clearTimeout(memoryDeleteTimerRef.current);
    memoryDeleteTimerRef.current = null;
  }
  setPendingDeleteMemoryId(null);
};
```

Add cleanup alongside the app's existing timer-cleanup effect (same pattern used for
mission timers):

```tsx
useEffect(() => () => {
  if (memoryDeleteTimerRef.current) window.clearTimeout(memoryDeleteTimerRef.current);
}, []);
```

### 4.3 Hide the pending card immediately

Filter `pendingDeleteMemoryId` out of the rendered list so the card disappears the
instant the trash icon is tapped, before the server call actually happens:

```tsx
const visibleMemories = useMemo(
  () => sortedMemories.filter((entry) => entry.id !== pendingDeleteMemoryId),
  [sortedMemories, pendingDeleteMemoryId]
);
```

Render `visibleMemories.map(...)` instead of `sortedMemories.map(...)`.

### 4.4 Undo toast

Reuse the existing `.skip-undo-toast` component/class from the missions flow — it's
already generic (no mission-specific styling), so no new CSS is required:

```jsx
{pendingDeleteMemoryId ? (
  <aside className="skip-undo-toast" role="status" aria-live="polite">
    <span>{text.memoryDeleted}</span>
    <button type="button" onClick={undoMemoryDelete}>{text.memoryUndoDelete}</button>
  </aside>
) : null}
```

Place it alongside the existing `skipUndoMissionId` toast near the bottom of the
component (both can coexist independently — they're keyed off different state).

### 4.5 New copy keys (`copy.en` / `copy.pl`)

```ts
// en
memoryDeleted: 'Memory removed.',
memoryUndoDelete: 'Undo',
// pl
memoryDeleted: 'Wspomnienie usunięte.',
memoryUndoDelete: 'Cofnij',
```

### 4.6 Edge cases to handle

- Switching world tabs (Old World ↔ New World) or leaving the Memories tab while a
  delete is pending: let the pending delete continue running in the background on its
  own timer (don't cancel it just because the child navigated away) — it will commit
  normally when the timer elapses, same as how mission skip behaves if you leave the
  Missions tab.
- If the child re-adds a memory or refreshes data (`fetchMemories`/`fetchAllMemories`)
  while a delete is pending, `visibleMemories` filtering still hides the pending item
  even after a refetch, since the filter is keyed on `pendingDeleteMemoryId`, not on
  when the fetch happened.

## 5. Acceptance Checklist

- [ ] Favorite star and delete icons are inline SVG, not emoji — visually clear and
      consistently sized across browsers/platforms.
- [ ] Filled gold star for favorited memories, outline star otherwise; both use the
      same visible size.
- [ ] Both icon buttons keep a minimum 44×44px (star) / 40×40px (delete) touch target
      even though the visible icon itself is smaller than the hit area.
- [ ] Favorited memories always appear above non-favorited ones in the list; within
      each group, newest-first ordering is preserved.
- [ ] Unfavoriting a memory removes it from the pinned group and re-inserts it at its
      normal date position among non-favorites — no jump to top or bottom.
- [ ] Tapping delete hides the card immediately and shows an undo toast for 4 seconds,
      matching the mission "Not today" timing.
- [ ] Tapping `Undo` restores the card with no API call made — nothing was actually
      deleted.
- [ ] If the undo window elapses without action, `DELETE /api/memories/{id}` is called
      and the list refreshes normally.
- [ ] Starting a second delete while one is already pending commits the first
      immediately rather than silently dropping it.
- [ ] `memoryDeleted` / `memoryUndoDelete` copy keys exist in both `en` and `pl`.
