- Make same-request/same-run activation idempotent and ownership-safe.

### 1.2 Out of scope

- New dynamic setup, input-safety, output-review or mechanics behavior.

## 2. Atomicity contract

For dynamic activation, one transaction must either publish all of the following or publish none:

- verified dynamic snapshot v2 with the requested run ID;
- source-neutral `DynamicGameRef` and game fingerprint;
- ACTIVE/ENDED status derived from the snapshot;
- initial revision and provider-call count;
- created/updated/last-played timestamps;
- current-run eligibility for the owner.

For replacement, the same transaction additionally suspends the exact expected current ACTIVE run. A failure before commit leaves that run ACTIVE and current. Never suspend first and create the replacement later.

Validation occurs before mutation. Reject null, Pack, unsupported-version, mismatched run ID, invalid bundle/fingerprint, invalid state/artifact or non-resumable snapshots. The store does not call a provider or regenerate anything.

## 3. Result semantics

Freeze `CreateOutcome` behavior:

| Condition | Result |
| --- | --- |
| New verified dynamic run and no open owner run | `CREATED` |
| Same run already exists for same owner with canonical-equivalent immutable snapshot identity | `EXISTS_SAME_OWNER`; no mutation |
| Run ID belongs to another owner | `EXISTS_OTHER_OWNER`; no information leak beyond mapped session error |
| Owner has another ACTIVE/PREPARING run | `OWNER_HAS_ACTIVE`; no mutation |
| Replacement expected run missing, wrong owner, not ACTIVE or no longer current | conflict outcome; no mutation |
| Snapshot verification/store write fails | exception/service failure; no partial state |

`RunSessionService` maps these consistently to existing bounded session error codes. It must not return a summary for a run that was not created and must not convert a durable I/O failure into `RUN_UNRECOVERABLE` for an otherwise valid run.

## 4. Verification before publication

`RunSessionService.activateDynamic` and replacement must:

1. Rewrite only the runtime run ID through the existing safe helper.
2. Verify dynamic bundle and snapshot invariants.
3. Resume in a fresh engine instance with zero blueprint calls and zero accepted-artifact calls.
4. Confirm resumed view/state/fingerprints agree with the snapshot.
5. Call the repository transaction only after verification.
6. Reload the stored row and return its source-neutral summary.

The resume verification must not mutate the snapshot, cache, provider ledger or prior run. Provider doubles in tests throw on every call.

## 5. Store transaction behavior

### 5.1 In-memory store

Synchronize the complete check-and-publish sequence. Test owner/run conflicts, replacement, idempotent replay and invalid snapshots. Returned and stored snapshots remain immutable/deeply isolated from caller mutation.

### 5.2 Local store

Perform the complete operation inside one existing `readWrite`/transaction commit. A fault before atomic file replacement must leave the previous valid primary or backup recoverable. Reopen must yield either the complete old state or complete new state, never suspended-old/missing-new.

Store v5 wire identity must agree with the embedded snapshot:

- Pack row: Pack identity and snapshot v1;
- dynamic row: profile identity/game fingerprint and snapshot v2;
- never both or neither.

Do not change the Pack v1 JSON representation.

## 6. Pack fresh-process recovery regression

Reproduce the frozen Willow Marsh partial route exactly:

```text
process A: start generated Pack offline, accept four choices, /save, /quit
process B: reopen same store with --continue, accept remaining four choices
expected: PARTIAL_SUCCESS, revision 8, zero provider calls
```

The current failure is a defect, not an expected incompatibility. Diagnose the concrete `ResumeResult` issue before changing code. Fix the narrow underlying cause while preserving these rules:

- restored accepted generation artifacts remain authoritative;
- no provider call or artifact regeneration on resume;
- every visited generated scene required by the runtime is restored;
- future unresolved scenes may use the saved Pack fallback/pipeline contract;
- command/effect/objective application is not duplicated;
- process B uses a fresh engine and a reopened `LocalSessionStore`.

Add a focused regression test that asserts the underlying resume issue code as well as a CLI/process route test. Do not rely only on the player-facing `RUN_UNRECOVERABLE` wrapper.

## 7. Dynamic recovery regression matrix

Add tests for:

- activate dynamic run, close/reopen store, resume/view without provider calls;
- accept a command, close/reopen, continue with exact revision/state/artifacts;
- replacement suspends old and publishes new atomically;
- injected replacement failure preserves old ACTIVE run/current marker;
- invalid/tampered bundle fails before any row/current-marker change;
- same-owner replay does not reset revision/timestamps/usage;
- other-owner run ID collision is rejected;
- ended dynamic run reopens as ENDED without generation;
- dynamic provider counters and fingerprints round-trip exactly;
- Pack and dynamic runs remain independently readable after store migration.

## 8. Failure injection

Use a small test repository/transaction decorator or existing fault hooks to fail at meaningful boundaries:

- before validation completes;
- after validation but before mutation;
- while staging replacement;
- before primary atomic move;
- after primary write but before backup refresh where the existing store recovery contract permits it.

Assert no false success, no orphan run, no double current run, no lost old snapshot and recoverability on reopen. Do not add production-only complexity solely for tests when a package-private test seam/decorator suffices.
