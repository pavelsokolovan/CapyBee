# Spec 27.1 — Durable Local Session Store (`--store-dir`)

**Type:** Implementation specification
**Parent:** Spec 27 — Engine API Contract (§7.1 ports, §9 algorithms, §10/§10.1 ledger and prefetch, §14.1 local console)
**Status:** Draft — grounded in repo commit `45751e1` ("engine - spec 27 partly implemented"). Builds/tests were **not** re-run during this investigation.
**Primary outcome:** With `--store-dir`, closing and restarting the console loses nothing: the run, pending start data, command log (with payload MACs and results), ordered event outbox, prefetched artifacts and generation usage/reservations are all restored consistently, written atomically, and cleaned up completely on delete. A bad store fails loudly with a stable code; it never half-restores.

**Scope note.** Spec 27's gap analysis has three parts: (1) durable local session, (2) console options and test coverage, (3) prefetch behavior and diagnostics. Parts 2 and 3 depend on part 1. **This spec is part 1 only.** Parts 2 and 3 become 27.2 and 27.3 and must not start before 27.1 is done.

## 2. Goals

1. One file-backed adapter, `LocalSessionStore`, implements **all** session ports and is the only thing wired in when `--store-dir` is set.
2. A documented, versioned, strictly validated on-disk format.
3. Every state change is an atomic, durable replace of that file; `Transaction.execute` is truly all-or-nothing.
4. A second console (process or JVM-local instance) cannot silently overwrite a store that is in use.
5. Delete and start/fail cleanup are complete by construction.
6. Corrupt, unknown-version or legacy stores produce one explicit, stable error and are left untouched.
7. Same semantics as `InMemorySessionStore` for every shared behavior, proven by one contract test run against both.

## 3. Non-goals

- Console flags `--prefetch`, `--calls-per-day`, `--run-calls`, in-session command polish, diagnostics line fields (→ 27.2 / 27.3).
- Prefetch behavior changes (hit/miss reporting, `sceneSource`) (→ 27.3).
- Multi-machine or server use. The Postgres implementation (Spec 27 §13) is untouched. `LocalSessionStore` is **local PC only**.
- Encryption at rest. The store holds child free-text (see §10); this is a developer's own PC and the file is plain JSON. Documented, not solved.
- Migration of old `<uuid>.json` run files (see D5).
- Changing `RunSessionService` behavior beyond §9.

## 4. Design decisions

| ID | Decision | Why |
|---|---|---|
| D1 | **One document, one file**: `<store-dir>/session-store.json` holds everything (runs with their commands/outbox/prefetch, plus the ledger). | A single atomic file replace gives a genuinely atomic `Transaction` across run + outbox + command with no journal or multi-file protocol. Local scale is tiny (≤1 open run per owner, snapshot ≤ 256 KB, small events). |
| D2 | Commands, outbox and prefetch are **nested inside their run record**. Ledger lives in its own top-level section. | Deleting a run record deletes its commands/events/prefetch by construction; other runs cannot be reached by accident. Daily usage must **survive** run deletion (deleting a run must not refund budget). |
| D3 | In-memory working state + `ReentrantLock`; commit = serialize whole document → temp file → `fsync` → atomic replace. Rollback = reload last committed state. | Simple, easy to test, no partial states. |
| D4 | Exclusive OS lock on `session-store.lock` for the lifetime of the store instance. | "Prevent concurrent writers from silently overwriting": the second opener fails with `STORE_LOCKED` instead of racing. |
| D5 | Legacy per-run `<uuid>.json` files are **not** imported. If found and no `session-store.json` exists → `STORE_LEGACY_LAYOUT`. | Dev-only data; an importer is extra surface. The error tells the user to pick a new `--store-dir`. |
| D6 | Strict parse: unknown fields, wrong types, bad enums, broken invariants ⇒ `STORE_CORRUPT`. Whole open fails; nothing is repaired or rewritten. | "Explicit error rather than partially restored session." |
| D7 | New composite port `SessionPorts.SessionStore` = all six ports. `InMemorySessionStore` and `LocalSessionStore` both implement it; `ConsoleApp` holds **one** `SessionStore` reference. | Removes the "passed the same object 5×, forgot one" bug class (E1). |
| D8 | Command-MAC key for the local store is random, created on first open, persisted in `session-store.key`. The in-memory console path keeps `new byte[32]` (documented as non-persistent). | Fixes E8 without server config. |
| D9 | Reservations are **conservative across crashes**: a reserved-but-unreleased call stays counted after a crash/kill. | Budget is never under-counted. |

## 5. On-disk format (version 1)

Version 1 is the original format implemented by Spec 27.1. Spec 27.3 advances the current format to version 2, migrates v1 documents in memory on read, and writes v2 on the next change; see Spec 27.3 §7 for command diagnostics and per-run prefetch counts.

### 5.1 Files

```
<store-dir>/
  session-store.json        committed document (the only source of truth)
  session-store.json.tmp    transient; exists only during a commit
  session-store.lock        OS lock file (empty)
  session-store.key         32 random bytes, Base64 text, command-MAC key (D8)
```

Create `<store-dir>` if missing. Set owner-only permissions on `session-store.json` and `.key` where the filesystem supports POSIX permissions; ignore silently on Windows.

### 5.2 Document

UTF-8 JSON, written compact (one line) by `SessionJson`. Instants are ISO-8601 strings, UUIDs are strings, `payloadMac` is Base64.

```jsonc
{
  "format": "capybee-session-store",
  "formatVersion": 1,
  "storeRevision": 42,                 // +1 on every commit; informational + sanity checks
  "writtenAt": "2026-10-19T10:00:00Z",
  "runs": [ RunRecord, ... ],          // ordered by createdAt
  "ledger": {
    "days":     [ { "scope": "profile:local", "day": "2026-10-19",
                    "reservedCalls": 5, "inputTokens": 1200, "outputTokens": 800, "prefetchCalls": 2 } ],
    "runCalls": [ { "runId": "…", "calls": 3 } ]
  }
}
```

`RunRecord`:

```jsonc
{
  "id": "…", "owner": "local-console",
  "packId": "…", "packVersion": "1.0.0", "locale": "pl",
  "status": "ACTIVE",                  // PREPARING | ACTIVE | ENDED | FAILED
  "revision": 3,
  "snapshot": { /* SnapshotCodec.toJson output, embedded as a JSON object; null until ACTIVE */ },
  "pendingStart": { "id": "…", "packId": "…", "locale": "pl",
                    "startInputs": {…}, "seed": 7, "generated": true },   // non-null ONLY while PREPARING
  "leaseToken": null, "leaseUntil": null,
  "failureCode": null,
  "generationCalls": 3,
  "createdAt": "…", "updatedAt": "…",
  "commands": [ { "commandId": "…", "payloadMac": "<base64>", "state": "DONE",
                  "accepted": true, "revisionBefore": 2, "revisionAfter": 3,
                  "events": [ { "id": "…", "payload": {…} } ], "failureCode": null } ],
  "outbox": { "nextSeq": 8,
              "events": [ { "seq": 7, "commandId": "…|null", "revision": 3,
                            "event": { "id": "…", "payload": {…} }, "createdAt": "…" } ] },
  "prefetch": [ { "sceneId": "…", "basedOnRevision": 3, "artifact": { /* GenerationArtifactCodec */ } } ]
}
```

### 5.3 Validation on open (all must hold, else `STORE_CORRUPT` unless another code is named)

- `format` equals the magic string; `formatVersion` present and an integer. `> 1` ⇒ `STORE_VERSION_UNSUPPORTED` (details: `found`, `supported`). Missing/`< 1`/non-integer ⇒ `STORE_CORRUPT`.
- No unknown fields anywhere (Jackson `FAIL_ON_UNKNOWN_PROPERTIES` on; explicit check for the embedded `snapshot`/`artifact` objects is delegated to their codecs).
- Run ids unique; `owner`, `packId`, `locale` non-blank; enums valid; `revision ≥ 0`.
- `PREPARING` ⇒ `snapshot == null` and `pendingStart != null`. `ACTIVE`/`ENDED` ⇒ `snapshot` decodes with `SnapshotCodec` and `snapshot.step == revision`; `pendingStart == null`. `FAILED` ⇒ `pendingStart == null`, `failureCode != null`.
- Lease fields are both null or both set.
- Commands: unique `commandId`; `DONE` ⇒ `accepted != null`, `revisionAfter ≥ revisionBefore`; `FAILED` ⇒ `failureCode != null`; `IN_PROGRESS` ⇒ `revisionAfter == null`.
- Outbox: `seq` strictly increasing from 1 with **no gaps**; `nextSeq == last.seq + 1` (or 1 when empty).
- Prefetch: artifact decodes; `sceneId` unique per run; no `FALLBACK` outcome.
- Ledger: counts `≥ 0`; `(scope, day)` unique; `runCalls.runId` unique.
- Counts the file against a hard size cap (`16 MB`); larger ⇒ `STORE_CORRUPT` on read, `STORE_TOO_LARGE` on write.

Truncated/garbage/empty file ⇒ `STORE_CORRUPT`. Missing file with no legacy files ⇒ empty store (created on first commit).

## 7. Behavior

### 7.1 Locking and threads

- `open`: acquire `FileChannel.tryLock()` on `session-store.lock`. `null` or `OverlappingFileLockException` ⇒ `STORE_LOCKED` (the second instance in the same JVM is detected too). Then load + validate (§5.3). On any failure release the lock and throw; leave all files untouched (including a stale `.tmp`).
- After a **successful** load, delete a stale `session-store.json.tmp`.
- One `ReentrantLock` guards every public method, reads included. `synchronized`-style visibility is not enough because a transaction spans several calls.

### 7.2 Commit (durable + atomic)

1. Serialize the working document; bump `storeRevision`, set `writtenAt` from the injected clock; reject `> 16 MB` with `STORE_TOO_LARGE`.
2. Write bytes to `session-store.json.tmp` through a `FileChannel`; `force(true)`.
3. `Files.move(tmp, target, ATOMIC_MOVE, REPLACE_EXISTING)`. If `AtomicMoveNotSupportedException`, fall back to a plain replace (existing behavior; document that atomicity then depends on the OS).
4. Best-effort `fsync` of the directory (ignore failure; unsupported on Windows).
5. On any `IOException`: delete the `.tmp`, restore the working document from the last committed state, throw `STORE_WRITE_FAILED`.

Keep the last committed state as the committed JSON string (or an immutable copy) so rollback is a re-decode, not a hand-written undo.

### 7.3 `Transaction.execute(Runnable work)`

- Takes the lock; if already inside a transaction on this thread, just runs `work` (joins the outer one).
- Outermost: run `work`; if it returns, commit **once** (skip if nothing changed); if it throws **anything**, roll back to the last committed state and rethrow the **same** exception (a `SessionException` stays a `SessionException`, e.g. `REVISION_CONFLICT`).
- Outside `execute`, every mutating port method is its own one-operation transaction (auto-commit).
- Reads inside a transaction see the transaction's own uncommitted writes; other threads block until commit/rollback, so they never observe a half-applied transaction. This is safe because transaction bodies contain no provider calls (E6). Keep it that way: **never call `TextGenerator` inside `execute`.**

### 7.4 Port semantics

Copy `InMemorySessionStore` semantics unless stated. Items marked ★ differ from today and apply to both stores (InMemory change is small and listed in §9.5).

**RunRepository**
- `createPreparing`: owner-conflict rules unchanged (`EXISTS_SAME_OWNER`, `EXISTS_OTHER_OWNER`, `OWNER_HAS_ACTIVE` considers `PREPARING`/`ACTIVE` only). Stores `pendingStart` including raw `startInputs`.
- `find`/`findCurrent`/`tryClaim`/`delete` are owner-scoped. A different owner gets `empty`/no-op and learns nothing.
- ★ `tryClaim` succeeds only for `PREPARING`/`ACTIVE` runs (FileRunRepository rule, E10) when no unexpired lease exists; lease = `now + ttl` using the injected clock. Expired lease can be re-claimed with a new token.
- `saveActive`: needs matching lease token **and** `revision == expectedRevision`. Status `ENDED` if `snapshot.state().ended()` else `ACTIVE`; revision `expected` when the run was `PREPARING`, else `expected + 1`; **sets `pendingStart = null`, clears the lease**.
- `markFailed`: needs matching token; status `FAILED`, `failureCode` set, **`pendingStart = null`**, lease cleared. (Snapshot handling stays as today; see §12.)
- `releaseLease`: only the matching token; otherwise no-op.
- `delete(runId, owner)`: owner-checked; removes the whole run record (⇒ commands, outbox, prefetch) **and** that run's `ledger.runCalls` entry. **Does not touch `ledger.days`** (no budget refund). Deleting an unknown run is a no-op.
- ★ `StoredRun.generationCalls` reports the run's `ledger.runCalls` value.

**CommandLog**
- `begin`: `EXISTS` if the commandId is already in that run; otherwise `INSERTED` with state `IN_PROGRESS`. Unknown run ⇒ `IllegalStateException("RUN_NOT_FOUND")`.
- `complete`: requires a begun command, else `IllegalStateException("COMMAND_NOT_BEGUN")`; sets `DONE` with `accepted`, `revisionAfter`, `events`.
- `fail`: sets `FAILED` + code; silently ignores an unknown run/command (a late `fail` after delete must not throw).
- A commandId is scoped to its run: the same UUID in two runs is two independent entries.

**EventOutbox**
- `append` assigns `seq = nextSeq++` per run in list order; `nextSeq` is stored, so seqs are never reused. Unknown run ⇒ `IllegalStateException`. `readAfter` returns `seq > afterSeq`, ascending, up to `limit`; `limit < 1` ⇒ `IllegalArgumentException`; unknown run ⇒ empty.

**PrefetchStore**
- `insertIfAbsent`: `false` for `FALLBACK` outcome, for a duplicate scene, **and for an unknown (e.g. just-deleted) run** — a late prefetch job must never resurrect a deleted run. `load` returns insertion order. `deleteForScenes` ignores unknown ids.

**GenerationLedger**
- `tryReserveCall` / `recordUsage` / `releaseCall`: **identical arithmetic to `InMemorySessionStore`** (profile → global → run reserve rules, `PREFETCH` reserves, `max(0, …)` on release, `prefetchCalls` incremented in `recordUsage` for `PREFETCH`). Backed by `ledger.days` and `ledger.runCalls`.
- Each call is auto-committed immediately (a crash after the provider call must not lose the reservation, D9).
- ★ After a restart the same limits apply to the same `(scope, day)`; the day key comes from the caller's `LocalDate`.

## 8. Console wiring (`ConsoleApp.runSessionMode`)

```java
SessionPorts.SessionStore store; byte[] key;
if (options.storeDir() == null) { store = new InMemorySessionStore(clock); key = new byte[32]; }
else { LocalSessionStore local = LocalSessionStore.open(options.storeDir(), clock);
       store = local; key = local.commandKey(); }
```

- Pass `store` as `runs`, `commands`, `outbox`, `prefetch`, `transaction` **and** as the ledger inside `MeteredTextGenerator`. Remove the `FileRunRepository` import and the `memory` variable.
- Open the store in the same try-with-resources header **before** the executor: `try (LocalSessionStore …; ExecutorService workers = …)` so the executor drains first, then the lock is released. A late prefetch finishing during `/quit` is therefore persisted.
- Without `--store-dir`: behavior exactly as documented today (in-memory, lost on exit).
- Error handling: catch `StoreException` **before** `RuntimeException` and print on stderr one line `<CODE>` plus one plain hint line, exit code 3, no stack trace:

| Code | Hint |
|---|---|
| `STORE_LOCKED` | "This store is open in another console. Close it or use another --store-dir." |
| `STORE_CORRUPT` | "The store file is damaged and was left untouched." |
| `STORE_VERSION_UNSUPPORTED` | "The store was written by a newer version." |
| `STORE_LEGACY_LAYOUT` | "Old run files found. Use a new --store-dir." |
| `STORE_WRITE_FAILED` / `STORE_READ_FAILED` / `STORE_TOO_LARGE` | "Could not read or write the store; nothing was changed." |

- Update the `usage()` text for `--store-dir` to say it keeps runs, commands, events, prefetched scenes and usage.

## 9. Required changes to existing code (minimal)

1. `SessionPorts`: add `SessionStore` (D7). `InMemorySessionStore implements SessionPorts.SessionStore`.
2. `SnapshotCodec`: delegate artifact (de)serialization to `GenerationArtifactCodec` (§6.1).
3. `RunSessionService.processCommand` (and `processStart`): when the caught failure is a `StoreException`, complete the future with `SessionException(SERVICE_UNAVAILABLE)` instead of `RUN_UNRECOVERABLE`. A disk error must not look like a broken run, and must **not** mark the run `FAILED`. The command stays `IN_PROGRESS`; retrying the same `commandId` re-executes it once.
4. `RunSessionService.delete`: after `runs.delete`, drop in-flight prefetch futures for that run from `prefetchJobs` (late results are harmlessly rejected by `insertIfAbsent`, §7.4).
5. `InMemorySessionStore` parity (★): `tryClaim` status rule; `generationCalls` reported from its run-reservation counter.
6. Delete `FileRunRepository.java` and `FileRunRepositoryTest.java` (cases move to `LocalSessionStoreTest`).
7. Docs: add `docs/engine/local-session-store.md` (this spec's §5 plus the troubleshooting table in §8); update Spec 27 §14.1 ("`--store-dir` keeps all session data in `session-store.json`, see Spec 27.1") and the status/README line.

## 10. Privacy

- `pendingStart` holds raw free text and exists **only while `PREPARING`**. It is nulled in the same commit as `saveActive`/`markFailed`. A `PREPARING` run left by a crash keeps it (needed to retry) until `START_TIMEOUT` marks it `FAILED`.
- The store never logs. `StoreException.details` and `toString()` carry codes, counts and paths only — never snapshot, events, prompts, MACs or free text.
- The file contains snapshots, events and artifacts in clear text. State in `docs/engine/local-session-store.md` that `--store-dir` is for the developer's own machine.
- Test: a distinctive marker string in `startInputs` is absent from `session-store.json` after a successful start, and after `START_REJECTED`.

## 11. Required tests

All use `@TempDir`, injected fixed/advancing `Clock`, and the existing deterministic fake provider. Keep Jacoco ≥ 70% per package in `engine-session`.

### 11.1 `SessionStoreContractTest` (parameterized: `InMemorySessionStore`, `LocalSessionStore`)
createPreparing outcomes; claim/save/release with token and revision CAS; expired-lease takeover and old-token `saveActive == false`; `tryClaim` refused for `ENDED`/`FAILED`; command begin/complete/fail/`EXISTS`; outbox seq ordering and `readAfter` limits; prefetch rejects `FALLBACK`/duplicates; ledger reserve limits, `PREFETCH` reserves, `releaseCall` floor; `delete` cleanup; same `commandId` in two runs independent.

### 11.2 `LocalSessionStoreTest` — restart retention (open → work → `close()` → open a new instance on the same dir)
1. Run snapshot, revision, status restored.
2. A `DONE` command replays after restart through the **service**: `Outcome.REPLAYED`, same `appliedRevision` and events, no engine/provider work (fake call counter unchanged).
3. Outbox: ordering and gapless `seq` identical; a post-restart command continues at `nextSeq`, never reusing a number.
4. Prefetch artifacts present after restart (`diagnostics.readyPrefetch`); the next command consumes the stored scene with **zero** new provider calls for it.
5. Ledger: with profile limit 3 and 2 calls used, a restarted store permits exactly 1 more `DEMAND` call; run counter retained (`run-calls` ceiling and `StoredRun.generationCalls`); `tokens` and `prefetchCalls` retained.
6. `IN_PROGRESS` command left by a simulated crash (no `complete`): after restart, retrying the same `commandId` runs it exactly once; outbox has the events once.
7. `PREPARING` run with `pendingStart` after restart: `service.get` restarts the start and ends `ACTIVE` with `pendingStart` gone.
8. Stale `session-store.json.tmp` (garbage) next to a valid file: open succeeds, uses the main file, deletes the tmp.

### 11.3 Deletion and cleanup
After `service.delete`: the file contains **no** occurrence of the run id or any of its command ids (text search); `find`, `commands.find`, `readAfter`, `prefetch.load` are empty; `ledger.days` unchanged, `ledger.runCalls` entry gone; the owner can create a new run; deleting twice is a no-op; `insertIfAbsent` after delete returns `false`; `commands.fail` after delete does not throw.

### 11.4 Transaction and failure
- `execute` body does `saveActive` + `outbox.append` + `commands.complete` then throws ⇒ committed file bytes (hash) unchanged, in-memory reads unchanged, same exception type rethrown.
- Nested `execute`: inner throw rolls back the **outer** work too.
- Injected `StoreFiles` that fails at write ⇒ `STORE_WRITE_FAILED`, state rolled back, `.tmp` absent, the next operation succeeds.
- Reader thread never sees half a transaction (tx appends 2 events + bumps revision; reader sees both or neither), 1000 iterations.
- `close()` then any call ⇒ `STORE_CLOSED`.

### 11.5 Locking and concurrency
Second `open` on the same dir ⇒ `STORE_LOCKED`; after `close()` it opens. 8 threads × 50 appends/commands ⇒ after reopen: unique, gapless seqs and all commands present. Failed `open` (corrupt file) releases the lock.

### 11.6 Lease behavior
Unexpired lease persisted across restart blocks `tryClaim` (fixed clock); advancing the clock past `until` allows it; `releaseLease` with a wrong token is a no-op and persists nothing; service-level `RUN_BUSY` for a command while another holds the lease.

### 11.7 Malformed stored data (one parameterized test; each case asserts the exact `Code`, **file bytes unchanged**, lock released)
empty file; truncated JSON; trailing garbage; wrong `format`; missing `formatVersion`; `formatVersion: 2` ⇒ `STORE_VERSION_UNSUPPORTED`; unknown top-level field; unknown field in a run; duplicate run id; `ACTIVE` with null snapshot; snapshot with `step != revision`; undecodable snapshot; `PREPARING` without `pendingStart`; `ENDED` with `pendingStart`; bad status enum; outbox gap / wrong `nextSeq`; duplicate `commandId`; `DONE` command without `accepted`; prefetch artifact with unknown payload field; prefetch `FALLBACK`; negative ledger count; legacy `<uuid>.json` with no store file ⇒ `STORE_LEGACY_LAYOUT`. A directory that is a file, or unreadable ⇒ `STORE_READ_FAILED`.

### 11.8 Owner isolation
Owner B with owner A's `runId`: through the service `get/command/commandStatus/events/delete` ⇒ `RUN_NOT_FOUND` and A's data (file bytes) unchanged. At store level, `commands.find(runB, cmdOfA)`, `readAfter(runB, …)`, `prefetch.load(runB)` are empty and `delete(runA, ownerB)` is a no-op. `createPreparing` with A's run id and owner B ⇒ `EXISTS_OTHER_OWNER`.

### 11.9 Privacy
Marker string absent from the file after start success and after `START_REJECTED`; present while `PREPARING`; `StoreException.getMessage()/details` contain no marker.
