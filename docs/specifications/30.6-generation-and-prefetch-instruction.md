# Spec 30.6 — Generation and prefetch

**Intent:** [Illustrated Honeycomb RPG](intent/03-illustrated-honeycomb-rpg.md)
**Baseline:** `7d417fb`
**Status:** Implemented 2026-11-18; see [acceptance](../game-generation-prefetch-acceptance.md)

Connect the existing theme-first generation pipeline to trusted illustration
references and legal next-scene prefetch. Reuse safety review, authored fallback,
scene artifacts, bounded session fanout/concurrency, single-flight metering and
owner/run revision guards. Do not add browser generation or another cache.

Scene requests include the accepted theme explicitly and a bounded trusted
illustration context from the validated Pack presentation definition: player,
current scene backdrop, and only character asset IDs bound to that scene.
The provider may describe the scene consistently with this context; it cannot
choose new assets, return SVG/URLs, change bindings or authorize mechanics.
Existing strict output parsing rejects extra fields. Authored art bindings stay
authoritative, so failure or refusal cannot produce missing artwork or an error
screen. No raw wish is added to later scene prompts or persisted as a new field.

Prefetch candidates include enabled choice targets, the selected conditional
advance target, and eligible schema-2 MOVE entry targets. Deduplicate in stable
order and respect each slot's ON_ENTRY/PREFETCHABLE policy. For MOVE-derived candidates, current-place, disconnected, gated and
scene-restricted destinations are excluded. Preparing
content never enters a scene, changes revision, discovers a hero or recruits.
Existing session limits remain authoritative; disabled flags remain disabled.

Ship Pack 1.4.0 with the same mechanics/artwork and PREFETCHABLE non-ending scene slots; endings remain ON_ENTRY.
Retain exact 1.0.0–1.3.0 resources and timing for saved games. New runs select
1.4.0; extend only its unchanged reviewed completion bindings. No paid provider
is enabled by this work. Dynamic profiles retain their separate capabilities.

Test trusted prompt context, immutable public views during preparation,
conditional/disabled candidate filtering, fallback and provider-disabled resume.
Reuse session tests for bounded fanout, single-flight joins, stale workers and
truthful usage. Run standalone engine clean verify, exact backend verify and the
existing integrated deterministic browser suite. Verify packaged retained Pack
resources. Record acceptance in docs/game-generation-prefetch-acceptance.md and
commit on main. Visual release certification remains 30.7.
