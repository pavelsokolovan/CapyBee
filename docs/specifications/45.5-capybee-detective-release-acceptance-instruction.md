# Spec 45.5 — CapyBee Detective Release Acceptance

**Depends on** Specs 45.1–45.4 and the [web adventure verification workflow](../game-web-client.md#verification).

## Automated release gate

- Use the Spring-served web app, PostgreSQL, and the production dynamic game controllers with a deterministic test provider. Use separate eligible accounts for English and Polish and a younger account for the eligibility check.
- Start both cases from Play → Adventures. Complete both investigations through their final deduction. Verify the accepted case identity and revision survive a browser reload, an accusation remains gated by evidence, and the result cites the clues collected during play. Check English and Polish presentation on a mobile viewport.
- Simulate a provider outage during replacement. Confirm the saved case stays active and resume it without another start. Run the existing browser regression suite for both Polish adventures, the shared renderer, and recovery.
- Run both browser suites in CI. Keep fixture authentication and provider responses in test sources.

## Live release gate

- In staging, use the intended deployed profile version and an operator-approved provider and model. Play through a fresh English and Polish case. Check the logic of each reconstruction, the age-appropriate tone, scene text, mobile layout, and save and resume.
- Record the revision, profile version, model, locales, and pass or fail status. Keep credentials, raw responses, prompts, private suggestions, and saved game data out of the report. Record live verification as pending when the provider or approval is unavailable.
