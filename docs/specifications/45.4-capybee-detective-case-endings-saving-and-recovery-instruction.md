# Spec 45.4 — CapyBee Detective Case Endings, Saving and Recovery

**Depends on** [45.2](45.2-capybee-detective-ai-case-generation-and-validation-instruction.md), [45.3](45.3-capybee-detective-character-art-and-investigation-screens-instruction.md), and the shared adventure start and run recovery flows.

## Case endings

- Show the accepted result alongside the final scene. Distinguish solved, unresolved, failed, and abandoned cases with localized text. For a solved case, show the accepted reconstruction of the method, motive, timeline, and decisive clues. Keep the evidence available in Case Notes.
- Focus the result heading when the final choice is saved and when opening an already completed case. Keep the ending readable in text mode. Returning to Adventures opens the catalog.

## Saving and recovery

- Resume an active case through the existing saved-adventure entry with its accepted scene, choices, cast, and discovered clues. Keep the current adventure available while a replacement is being prepared. The server publishes a replacement only after generation and validation succeed.
- For a confirmed failure with detective settings still available, offer to review those settings for a retry. Clear the optional idea and ask again before replacing any active adventure. Submit a new generation request only after explicit confirmation.
- For an uncertain attempt, check the original operation using its saved identifier. Keep the identifier if the player resumes the existing case before the attempt is resolved. Only show the status-check action while an operation can be checked. Resuming a saved case and checking an attempt never submit a new start.

## Acceptance

- Verify the solved and unresolved presentations, keyboard focus, and the result in text mode.
- Verify a failed generation preserves an active case, retry requires confirmation and replacement consent, and an uncertain attempt checks its original operation without another start.
