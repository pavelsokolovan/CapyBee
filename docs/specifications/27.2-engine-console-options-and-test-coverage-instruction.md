# Spec 27.2 — Session Console Options, Error Handling and Test Coverage

**Type:** Implementation specification
**Parent:** Spec 27 — Engine API Contract (§14.1 local console, §15 required tests)
**Depends on:** Spec 27.1 — Durable Local Session Store (must be implemented first; this spec assumes `SessionPorts.SessionStore` and `LocalSessionStore` exist)
**Status:** Draft — grounded in repo commit `45751e1` ("engine - spec 27 partly implemented"). Builds/tests were **not** re-run during this investigation.
**Primary outcome:** The `--session` console behaves as Spec 27 §14.1 promises: the budget and prefetch switches exist, a slow command is polled correctly, errors show a stable code plus a hint instead of killing the game, and the behavior is locked in by deterministic golden and restart tests. After this spec, the console is a trustworthy way to test the engine by hand before any web work.

**Scope note.** Part 2 of 3 of the Spec 27 gap plan. Part 1 = 27.1 (durable store). Part 3 = 27.3 (prefetch behavior and diagnostics fields). This spec adds the *switch* for prefetch, but not new prefetch behavior.

## 2. Goals

1. Add `--prefetch on|off`, `--calls-per-day <n>`, `--run-calls <n>` with one single source of truth for limits.
2. Fix slow-command polling; print the thinking line once; make wait and poll timing injectable.
3. Never end a session because of a recoverable error; show `CODE` + hint; keep the exit-code contract.
4. Make start/resume flags unambiguous (`--new`, `--run`, silently ignored flags).
5. Make in-session input safe (unknown `/commands`, `q`, abandon confirmation, complete `?` help).
6. Close the Spec 27 §15 coverage gaps for `engine-session` (items 4–12) and the console (items 29–33), deterministically (no real sleeping, no network, no randomness).

## 3. Non-goals

- Prefetch behavior (reserves, fan-out, concurrency limit, hit/miss reporting, `sceneSource`) and the extra `--debug` fields (latency, `sceneSource`, budget left) → **27.3**. Prefetch tests 21–27 → **27.3**.
- Persistence → **27.1**.
- HTTP controllers, the service-vs-HTTP conformance test (item 28), `app/server` tests 13–17, UI tests 18–20 → later specs. The scenario set from §10.3 is written transport-neutral so it can be reused for item 28.
- Localizing hints (English only; the console is a developer tool).
- Changing the classic (non-session) console path, `--save/--load`, `--live-smoke`. They stay byte-for-byte compatible (item 33).

## 4. Design decisions

| ID | Decision | Why |
|---|---|---|
| D1 | `SessionLimits` is the single source of truth for budgets. It gains `profileCallsPerDay` and `prefetchEnabled`. `ConsoleApp` builds one `SessionLimits` from flags and derives `LedgerScope`s and the `MeteredTextGenerator` arguments from it. Reserves (8/100/4) stay constants until 27.3. | Removes E1's duplication. |
| D2 | `--calls-per-day n` sets **both** the profile and the global daily cap to `n` (the local console has one user). `0` is allowed (every call is refused ⇒ every stage uses its fallback). | Predictable cap rehearsal. |
| D3 | The three tuning flags are accepted with `--session` in any combination, also with `--run`. They only affect generated play and are no-ops for authored packs; this is documented, not an error. | A resumed generated run is not re-passed `--generated`, so rejecting would make rehearsal on resume impossible. |
| D4 | `--new` **deletes** the owner's current open run (via `service.delete`) and prints `Discarded previous run <id>.` before starting. Ended/failed runs stay. | Needed to start over; uniform for `PREPARING` and `ACTIVE`. Considered and not chosen: auto-abandon (needs a revision and lease, fails with `RUN_BUSY` after a crash). **Confirm this decision.** |
| D5 | `--run` cannot be combined with `--locale`, `--input`, `--seed`, `--generated` (parse error). Resuming the current run implicitly while any of those flags is present prints a one-line note and proceeds. | No silently ignored flags (E8). |
| D6 | Errors have two shapes: **startup/fatal** → stderr, two lines (`CODE`, then `  hint`), exit 3 (as in 27.1). **In-session recoverable** → stdout, one line `! CODE: hint`, game continues. | In-session errors are part of the transcript and must be golden-testable. |
| D7 | Timing is injected through a package-private `ConsoleTuning(syncWait, minPoll, maxPoll, maxWait, Sleeper)`. Production defaults: 8 s, 250 ms, 5 s, 3 min. The poll sleep is `retryAfterMs` clamped to `[minPoll, maxPoll]`. Tests use zero waits and a recording `Sleeper`. | E4 + testability. |
| D8 | Extract the session loop out of `ConsoleApp` into package-private `SessionConsole` (pure move first, then changes). Add `ConsoleErrors` (code → hint). | E12; smaller, reviewable diffs. |
| D9 | Abandon confirmation applies to interactive input only. Script mode (`--script`) never prompts. | Scripts must stay deterministic. |

## 5. Console options

### 5.1 New and changed flags (all require `--session`)

| Flag | Value | Meaning |
|---|---|---|
| `--prefetch on\|off` | case-insensitive `on`/`off` | Enables/disables scene prefetch. **Default: `on` when `--generated`, otherwise `off`.** Maps to `SessionLimits.prefetchEnabled`. |
| `--calls-per-day <n>` | integer `0..100000` | Profile **and** global daily call cap (D2). |
| `--run-calls <n>` | integer `1..1000` | Per-run lifetime call ceiling (`SessionLimits.runCalls`, also the diagnostics ceiling and the `MeteredTextGenerator` run limit). |

Parse errors (exit 2, message on stderr, one line each):
- missing value: `Missing value for --prefetch.` (same pattern for the other two);
- `--prefetch must be on or off.`;
- `--calls-per-day must be an integer from 0 to 100000.`; `--run-calls must be an integer from 1 to 1000.`;
- used without `--session`: extend the existing message to `--store-dir, --run, --new, --debug, --prefetch, --calls-per-day and --run-calls require --session.`;
- `--run` combined with `--locale`/`--input`/`--seed`/`--generated`: `--run cannot be combined with --locale, --input, --seed or --generated.`;
- `--help` still cannot be combined with anything (include the new flags in that check).

`ConsoleOptions` gains `Boolean prefetch` (null = default), `Integer callsPerDay`, `Integer runCalls`. Keep the existing public constructors working (they pass `null`s).

### 5.2 Service change for `prefetchEnabled`

`RunSessionService.ensurePrefetch` returns immediately when `!limits.prefetchEnabled()`. Nothing else about prefetch changes in this spec. Add a secondary `SessionLimits` constructor with the old five arguments (defaults: `profileCallsPerDay = 40`, `prefetchEnabled = true`) so existing callers and tests compile unchanged. Validation: `profileCallsPerDay ≥ 0`.

### 5.3 Start / resume semantics (decision table)

| Flags | Open run exists? | Behavior |
|---|---|---|
| `--run <id>` | any | Resume that run (any status). Unknown id or other owner ⇒ `RUN_NOT_FOUND`, exit 3. |
| (none) | yes | Resume the current open run. If any of `--locale/--input/--seed/--generated` is present print `Note: resuming run <id>; start options are ignored. Use --new to start over.` (stdout) and proceed. |
| (none) | no | Start a new run. |
| `--new` | yes | Delete it, print `Discarded previous run <id>.`, start a new run (D4). |
| `--new` | no | Start a new run. |

### 5.4 Usage text

Update `consoleUsage()` to list the new flags in one line each, and to say that `--session` without `--store-dir` keeps everything in memory only.

## 6. Session loop behavior

### 6.1 Slow commands (fixes E4, E5)

```
outcome = service.command(..., tuning.syncWait())
if outcome == PROCESSING:
    print "CapyBee is thinking…"            // once per command, own line
    id = outcome.commandId()                // SAME commandId for every poll
    waited = 0
    loop:
        status = service.commandStatus(owner, runId, id)   // may throw SessionException
        if !status.processing(): outcome = status.outcome(); break
        out.print("."); sleep(clamp(status.retryAfterMs()))
        waited += slept; if waited >= tuning.maxWait(): -> recoverable COMMAND_STILL_RUNNING (see below)
    if any dot printed: out.println()
```

- Never dereference `status.outcome()` while `status.processing()` is true.
- A *slow start* (`awaitActive`) uses the same pattern: the thinking line **once**, then dots.
- `COMMAND_STILL_RUNNING` is a console-local pseudo-code (not an `ErrorCode`): print `! COMMAND_STILL_RUNNING: CapyBee is still working. Wait a moment, then press Enter or type /status.` Keep the pending `commandId`; on the **next** input line, first poll that command once (and apply its outcome) before handling the new input.
- The revision used for the next command is always taken from a fresh `service.get`, never from a stale local copy.

### 6.2 Error handling (fixes E6, E10)

`SessionConsole` wraps each service call. Classification:

| Code | Class | Console action |
|---|---|---|
| `REVISION_CONFLICT` | recoverable | refresh summary, re-render view, continue |
| `RUN_BUSY` | recoverable | continue |
| `GENERATION_BUSY`, `RATE_LIMITED`, `GENERATION_UNAVAILABLE`, `SERVICE_UNAVAILABLE` | recoverable | continue |
| `REQUEST_INVALID`, `PAYLOAD_TOO_LARGE` | recoverable | continue |
| `RUN_NOT_ACTIVE` | refresh | refresh summary; if status is not `ACTIVE` print one status line (`Run ended.` / `Run failed: <code>.`) and exit 0 / 3 |
| `RUN_UNRECOVERABLE` | fatal | print code + hint, exit 3 |
| `RUN_NOT_FOUND`, `RUN_ALREADY_ACTIVE`, `START_REJECTED`, `START_TIMEOUT`, `COMMAND_ID_REUSED`, `INTERNAL_ERROR`, `GAME_DISABLED` | fatal | print code + hint, exit 3 |
| `StoreException` (27.1) | fatal | print `STORE_*` code + hint, exit 3 |
| any other `RuntimeException` | fatal | print `SESSION_UNAVAILABLE`, exit 3, **no stack trace, no message text** |

Hints (`ConsoleErrors`, one short English sentence each):

| Code | Hint |
|---|---|
| `REVISION_CONFLICT` | The run moved on. The current scene is shown again. |
| `RUN_BUSY` | The run is still locked by an earlier session. Wait up to 30 seconds and try again. |
| `GENERATION_BUSY` | Too many generation jobs are running. Try again in a moment. |
| `RATE_LIMITED` | The call budget for today is used up. Fallback scenes will be used. |
| `GENERATION_UNAVAILABLE` | The text provider is not available. Check GENERATION_MODEL_ID and ANTHROPIC_API_KEY. |
| `SERVICE_UNAVAILABLE` | The session could not save the change. Nothing was applied. Try again. |
| `REQUEST_INVALID` | The input was not accepted. Type ? for help. |
| `PAYLOAD_TOO_LARGE` | That text is too long. Shorten it. |
| `RUN_NOT_ACTIVE` | This run is not active any more. |
| `RUN_UNRECOVERABLE` | The saved run cannot be continued. Start a new run with --new. |
| `RUN_NOT_FOUND` | No such run for the local player. Omit --run to continue the current run. |
| `RUN_ALREADY_ACTIVE` | A run is already open. Continue it or use --new. |
| `START_REJECTED` | The pack or inputs were rejected. Check --pack-dir, --locale and --input. |
| `START_TIMEOUT` | Starting took too long. Run again with --new. |
| `COMMAND_ID_REUSED` / `INTERNAL_ERROR` | Unexpected internal error. Nothing was changed. |
| `GAME_DISABLED` | Game sessions are switched off. |

Never print `SessionException.details()` values except `existingRunId` for `RUN_ALREADY_ACTIVE` and `currentRevision` for `REVISION_CONFLICT`. Never print exception messages or stack traces.

**Exit codes:** `0` normal end, `/quit`, EOF, end of script; `2` argument/script errors (unchanged); `3` fatal session/store error; `4` live-smoke problems (unchanged). A recoverable error inside a script does **not** change the exit code.

### 6.3 Input rules (fixes E9)

- `/text <words>`, `/move <placeId>`, `/status`, `/events [afterSeq]`, `/debug on|off`, `/abandon`, `/quit` (alias `/q`), `?` and `/help` (same text). Update the help line to list all of them.
- **Unknown input starting with `/`** ⇒ `! Unknown command. Type ? for help.` It is **never** submitted as text. To send text that begins with `/`, use `/text`.
- Plain text in a `TEXT`/`CHOICE_OR_TEXT` scene is still submitted as before.
- `q` is an abandon alias **only if** the current view has no option whose id equals `q` (case-insensitive); otherwise it selects that option.
- Abandon (`/abandon`, or `q`) in interactive mode asks `Abandon this run for good? (y/N)`; anything other than `y`/`yes` cancels with `Cancelled.`. In `--script` mode no prompt (D9).
- `/events [afterSeq]` pages through the outbox (100 per call) until exhausted; output format per line unchanged (`<seq> <eventId>`); payloads are never printed.
- `/debug on|off` behaviour unchanged; the diagnostics line itself is unchanged (extended in 27.3).

### 6.4 Start-up flow

1. Parse flags, load pack (unchanged).
2. Build `SessionLimits` from flags (D1) and open the store (27.1).
3. Apply §5.3 (resume/start/`--new`).
4. Wait for `ACTIVE` with the §6.1 pattern (`START_REJECTED`/`START_TIMEOUT`/`FAILED` ⇒ fatal with hint).
5. Print the header (`Run <id>`, `Running <pack> in locale <locale>`) and the view as today.

## 8. Test infrastructure (add first)

- `MutableClock` (test util): settable instant; used for lease expiry and day rollover. Replaces `Clock.fixed` in new tests; existing tests keep theirs.
- `RecordingSleeper`: records requested durations, returns immediately; optional hook to advance a `MutableClock`.
- `GatedGenerator` (fake `TextGenerator`): blocks inside `generate` on a latch, counts calls, can be released or made to fail. Plus a deterministic **answer-by-stage** fake (replaces the order-dependent `ScriptedGenerator` queue for session tests) so output does not depend on call order.
- `Transcripts.normalize(String)`: replaces UUIDs with `<uuid>` and `\r\n` with `\n` before comparing to golden files (E13).
- All new tests: no network, no real sleeping, no wall-clock dependence, `@TempDir` for stores.

## 11. Implementation sequence
